# Privacy, security, licensing, and claim audit

## Privacy and secrets

- runtime binds to loopback by default;
- no telemetry, analytics, cookies, accounts, marketplace, or remote integration;
- no environment credential is required or read;
- HTTP uploads are limited to 1 MB, processed in memory, and not persisted;
- CLI persistence occurs only at the operator-supplied output path;
- server logging suppresses request content;
- repository secret scan and tracked-file inventory are recorded in the final validation receipt.

## Prompt injection and browser surface

- runtime has no model call;
- imported strings are never passed to `eval`, a shell, SQL, a template engine, a path resolver, or a command runner;
- dynamic DOM content uses `textContent`, not `innerHTML`;
- CSP restricts resources to self and denies objects, frames, base changes, and foreign form actions;
- exact static/API routes prevent path traversal;
- non-loopback binding requires an explicit CLI override;
- Host and Origin checks reject non-loopback request authorities before routing unless that override is explicit;
- request size and JSON content type fail closed;
- exact duplicate JSON keys, unsupported object fields, and non-boolean materiality fail closed before reduction;
- source/receipt/checkpoint causal times prevent later evidence from supporting an earlier claim;
- required receipt ID/hash pointers prevent silent overwrite or unsafe rollback across checkpoints;
- machine success conditions remain false while their subject or validation lineage is disputed;
- the synthetic embedded instruction remains visible as evidence with zero state authority.

Safe wording: `instruction text is inert by construction in this local deterministic runtime`. Do not claim that general prompt injection has been solved.

## Authority and validation limitations

The local authority source-kind registry and trusted validator-ID set are deterministic fixture policies. An untrusted package is structurally checked, but the MVP has no signature, identity provider, remote attestation, or production IAM. A malicious producer could impersonate a recognized string. This boundary is acceptable for the synthetic judge demo and must not be represented as authenticated authorization.

## Integrity and recovery limitations

SHA-256 detects changes to normalized canonical checkpoint content, source-record identity, and retained receipt identity. It does not preserve raw-input byte identity or prove source truth or authorship. Recovery is verified for a corrupted or semantically invalid primary checkpoint with a valid fallback and lineage-safe tail replay; ambiguous receipt lineage stops rather than being guessed. It does not prove recovery from disk loss, database corruption, power failure, or a broken full event chain.
